**The zero in the skipped row is the figure to read.** The seven
`DatabaseLevelAuditGuardTests` are PostgreSQL-only — they assert that
the SCMS-SR-006 trigger refuses an UPDATE or DELETE issued as raw SQL,
which SQLite has no trigger to refuse. On SQLite they skip, and a run
where they skipped would otherwise look identical to a run where they
passed. On CI they run.

For comparison, the same suite on SQLite locally:

```

OK (skipped=7)
```

Lint (`flake8 complaints config`) and the missing-migration check
(`makemigrations --check --dry-run`) both pass in the same run. A third
job builds the container image, refuses it if it runs as root, starts
the stack with PostgreSQL and smoke-tests the running application.

### What is excluded, and why

From `.coveragerc`, each with its reason recorded there:

| Excluded | Reason |
|---|---|
| `*/migrations/*` | generated by Django, not written by the team |
| `*/tests.py` | measuring the tests with the tests says nothing |
| `manage.py`, `wsgi.py`, `asgi.py` | entry points, exercised by running at all |
| `config/settings_local.py` | the local-development override; CI runs on PostgreSQL |

### The uncovered 86 lines

Concentrated in three places, all of them deliberate:

- **`complaints/admin.py`, 23 lines (79.3%)** — Django admin list
  displays and read-only guards. Reached through the admin UI, which
  the suite does not drive.
- **`complaints/views.py`, 23 lines (89.7%)** — mostly branches that
  need a misconfigured deployment to reach (a missing file on disk, a
  storage backend error).
- **`complaints/management/commands/archive_expired_complaints.py`,
  5 lines (72.2%)** — the command's own error reporting. The
  `archive_expired()` function it calls is covered at 96.2%.

```
coverage report --rcfile=../.coveragerc
```
